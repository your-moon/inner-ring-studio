# Product

## Register

product

## Users

Developers, data operators, and technical teams who work directly with PostgreSQL, MySQL, or ClickHouse. They use Inner Ring Studio in focused desktop and browser sessions to inspect schemas, browse and edit records, run SQL, manage connections, and move safely between local, staging, and production databases.

## Product Purpose

Inner Ring Studio is a fast, self-hosted database workspace with an encrypted, git-synced connection vault. It should make database work feel immediate and navigable while preserving the context and safety needed for production data. Success means users can resume real work quickly, understand connection health and environment at a glance, and complete common database tasks without fighting the interface.

## Brand Personality

Precise, calm, and capable. The interface should earn the quiet confidence associated with Linear and Attio: dense without feeling cramped, refined without decoration, and predictable enough to disappear into the user's task.

## Anti-references

Do not resemble a terminal skin, a generic admin template, or a Material-style control collage. Avoid heavy gridlines, bold monospace everywhere, redundant search boxes, unlabeled icon rails, floating action buttons, disconnected shells, excessive cards, ornamental gradients, and motion that does not explain a state change.

## Design Principles

1. Resume work, not destinations. Home and navigation should restore useful context such as recent tables and actual queries.
2. Structure should be felt, not announced. Use surface hierarchy, spacing, and restrained typography instead of excessive borders and chrome.
3. Safety should be visible at the moment it matters. Environments, read-only state, connection health, and production write confirmation must remain legible without creating alarm fatigue.
4. One coherent workspace. Home, studio, dialogs, overlays, and component states should share the same interaction and visual grammar.
5. Dense workflows deserve quiet precision. Prefer familiar controls, keyboard access, and meaningful micro-interactions over novelty.

## Accessibility & Inclusion

Maintain keyboard-operable workflows, visible focus states, semantic labels for icon controls, readable contrast in both themes, and reduced-motion behavior. Do not rely on color alone for environment, health, selection, or destructive state. No formal conformance target is currently documented; changes should preserve or improve practical WCAG 2.1 AA behavior.
